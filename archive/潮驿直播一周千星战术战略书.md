# 潮驿 Chaoyi Live · 一周冲 1000 Star 战术战略书

> 目的：把 `chaoyi-kitchen`（开源发布为 **chaoyi-live**）在一周内推到 **GitHub 1000 stars**。
> 受众：你自己（操盘人）+ 可动员的 1–2 名协助者。
> 基线判断：优质 OSS 首周通常 200–500 star；**1000 是进取目标**，靠"强定位 + 多通道齐发 + 既有受众杠杆 + 社区互动"可达。

---

## 一、战略层（Why it can win）

**1. 定位切口（一句话记忆点）**
> "类 Owncast，但更现代：四端打通 + 合规内置 + 中文友好 + 一键自托管"

可比对象：Owncast（~11.5k⭐, MIT, 自托管直播）验证了需求；但 Owncast 偏单人电台、无社交/移动端。**潮驿补的是"现代四端 + 社交 + 合规"空白**——这是能讲出的差异化故事。

**2. 现有资产杠杆（你已具备，别人没有）**
- 已有一篇**过审的掘金架构长文**（6 章，带外链）——首发当天直接导流。
- **FMCG 分销 SaaS 冲 1000 star 的实战经验**——方法论可复用（架构文 + 软文 + 社区）。
- 仓库本身**工程完成度高**：62 单测 + E2E + Docker 一键起 + 四端代码——star 进来的人"能跑起来"，留存高、二次传播强。

**3. 叙事人设**
独立/小团队开发者，认真做"合规内置的开源直播平台"，公开 roadmap、公开踩坑（SRS WebRTC 接入、四端契约）。**透明 + 技术深度 = 信任 = star**。

## 七、合规红线（务必守住）

- 开源**代码**不需要牌照；但你方**不能以开源为名实际运营无牌公开直播服务（尤其含打赏）**——否则照样踩牌照。
- 仓库内合规 hooks（年龄门禁/审核/打赏限额）**保持默认开启且不得提交绕过代码**（已写入 CONTRIBUTING.md）。
- 对外口径统一："可自托管的开源软件"，不承诺"已持牌运营"。
