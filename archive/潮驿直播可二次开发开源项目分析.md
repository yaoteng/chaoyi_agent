## 4. 许可证与合规注意（法务视角）

- **宽松许可（可闭源/自由集成）**：SRS、LiveKit(Apache-2.0)、MediaMTX、ZLMediaKit、Owncast、flv.js、hls.js、Video.js、GSYVideoPlayer、ExoPlayer、livego 均为 MIT / Apache-2.0——**可自由二次开发、可闭源运营**（保留版权声明即可）。
- **强 Copyleft（AGPL-3.0）**：Mastodon / Misskey / Lemmy。**若修改并网络提供服务，须开放修改后源码**。因为我们本就走开源路线，影响可控；但若未来某模块想闭源，应避免基于 AGPL 项目派生。
- **SRS 已在用且 MIT**，无许可风险；LiveKit Apache-2.0 同样友好。
- **商标/品牌**：Fork 他人项目需遵守其 trademark policy（如 Mastodon 字样限制），改名即可规避。

## 5. 与现有代码/方案的关系

- **已在用**：SRS（推拉流）、flv.js / hls.js（兜底播放）——本分析仅确认其成熟度与可扩展性，无需替换。
- **建议新增**：LiveKit（语音房/连麦），用其 SFU + 客户端 SDK 补强"实时互动"短板（SRS 偏单向直播）。
- **开源路线对接**：Owncast 作为"可自建直播+聊天"范本，验证我们《开源化战略方案》的可行性；其 MIT 许可可参考其架构。
- **社交层**：沿用自建 Node 后端（含匹配/礼物/合规），Misskey 仅作可选联邦底座。

## 6. 落地优先级（二次开发路线）

1. **立即可用（已验证）**：SRS + flv.js + hls.js → 维持现状，补文档。
2. **短期增强**：引入 **LiveKit** 做语音房/连麦 POC（对标 Soul/漂漂 的轻社交）。
3. **UI 外壳**：用 **Video.js** 封装直播观看页（弹幕/礼物/连麦叠加）。
4. **移动端**：Android 接入 **GSYVideoPlayer**（或 ExoPlayer）。
5. **可选**：社交层自建 or 引入 **Misskey**；开源整体参考 **Owncast** 架构。
