# 潮驿直播 × 炒意厨房 业务合并方案

> **触发**：用户指出两家业务重叠过多，建议合并、以潮驿理念为主打、兼顾两家特长。
> **版本**：v1.0 ｜ **日期**：2026-09-03 ｜ **性质**：品牌/产品/技术整合策略（PM + 法务共审）
> **配套**：《潮驿直播竞品分析报告》《潮驿直播PRD》《合规检查清单》《牌照资质路线图》《开源化战略方案》（同目录）

---

## 0. 结论先行

- **合并是必然且低成本的**：同源品牌（潮驿/炒意 同根 cháoyì）、同技术底座（chaoyi-kitchen 即四端 WebRTC 直播 monorepo）、同受众（年轻人/生活方式）、同形态（直播社交）。不合并只会双品牌内耗、重复研发、牌照双份、用户割裂。
- **品牌架构**：**潮驿（Chaoyi）= 母品牌/平台**（"年轻人的生活驿站"），**炒意厨房 = 站内美食垂类旗舰频道/IP**（潮驿·炒意厨房）。潮驿理念主打，炒意厨房的"美食/烹饪/陪伴"特长作为第一个、也是标杆垂类承载。
- **关键澄清**：技术层面**已经是一家**——chaoyi-kitchen 这个仓库就是当下的直播产品代码库（四端、WebRTC+FLV/HLS、LiveStream 模型、合规 hooks 都在里面）。因此合并主要是**品牌与定位收敛**，不是重写系统。
- **合规与开源**：以潮驿的合规框架为全平台标准；可整体走上一方案的"开源可自建平台 + 炒意厨房作美食垂类参考"路线。

## 1. 为什么合并（重叠分析）

| 维度 | 炒意厨房 | 潮驿直播 | 重叠/关系 |
|---|---|---|---|
| 品牌 | 炒意（chǎo yì） | 潮驿（cháo yì） | **同根近似音**，明显同一品牌家族 |
| 技术 | chaoyi-kitchen 四端直播 monorepo | 同一仓库衍生 | **同一代码库** |
| 受众 | 年轻人 / 美食生活 | 18–40 年轻人 / 潮流生活 | **高度重叠** |
| 形态 | 美食直播 / 烹饪内容 | 直播社交 / 兴趣同好 | **都靠直播** |
| 主张 | （美食）生活化 | 生活驿站、陪伴式 | 精神一致 |

**不合并的代价**：双品牌抢同一批用户、两套 PR/运营、两份牌照申请、代码分叉难以统一合规。

## 2. 合并后的品牌架构

```
潮驿 Chaoyi（母品牌 / 平台）
├─ 主张：年轻人的生活驿站（合规 · 兴趣同好 · 本地陪伴）
├─ 形态：直播社交平台（观看/开播/弹幕/合规打赏/匹配/语音房/本地驿站）
└─ 垂类频道（verticals）
   ├─ 炒意厨房（美食/烹饪旗舰垂类，首发标杆）
   ├─ 潮玩（规划）
   ├─ 穿搭（规划）
   └─ 手作（规划）
```

- **对外主打**：一律以"潮驿直播 / 潮驿·生活驿站"出现；炒意厨房作为"站内最火的美食垂类"被反复提及，强化"潮驿里有超棒的美食频道"。
- **对内**：炒意厨房团队/内容/主播作为垂类运营单元保留，享受平台全部能力（合规、匹配、语音房、本地驿站）。

## 3. 产品与内容整合

| 层 | 归属 | 内容 |
|---|---|---|
| **平台层** | 潮驿 | 直播观看/开播、弹幕、合规版打赏、兴趣标签匹配、语音房/群聊派对、本地驿站(LBS)、内容安全中台、创作者健康分 |
| **垂类层** | 炒意厨房（首发） | 美食直播、烹饪教程、美食社群、美食达人；作为"合规 · 兴趣 · 陪伴"理念的样板间 |
| **扩展层** | 规划 | 潮玩/穿搭/手作等垂类，复用平台层能力 |

- 炒意厨房**现有内容、主播、社群平滑迁入**潮驿，无需重建。
- 美食垂类天然**低风险、强合规友好**（避开秀场/团播雷区），最适合做冷启动标杆，反哺平台合规口碑。

---

## 4. 技术整合（低成本，因为本就同源）

- **单一 monorepo**：chaoyi-kitchen 即潮驿平台代码库；炒意厨房降为"美食垂类模块 / 频道配置"，不另起仓库。
- **复用资产**：四端（Web/KMP/鸿蒙/小程序）、WebRTC 推拉流 + FLV/HLS 兜底、`LiveStream` 模型、合规 hooks（年龄门禁/打赏限额/审核接口预留）。
- **避免双份**：不复制后端/前端；统一部署、统一监控、统一合规中台。
- **命名建议**（二选一，待确认）：
  - 方案甲：仓库改名 `chaoyi-live`（平台），内含 `kitchen` 垂类模块；
  - 方案乙：保持 `chaoyi-kitchen` 仓名，内部以 `chaoyi` 平台域 + `kitchen` 垂类组织（改动最小）。

---

## 5. 合规统一（以潮驿为准，且合并更省）

- 潮驿的合规框架（PRD §8 / 合规检查清单 L1–L6）作为**全平台标准**，炒意厨房同样适用。
- **合并的合规红利**：单一运营主体 → 牌照一次申请覆盖全业务（比双品牌省一份 ICP 证/网文证主体成本）；内容安全中台统一，审计更简单。
- 美食垂类作为低风险样板，利于合规冷启动与对外背书。

---

## 6. 开源路线（承接《开源化战略方案》）

- 合并后的"潮驿"整体作为**开源、可自建的直播社交平台套件**发布；
- **炒意厨房 = 官方参考美食垂类**（demo/模板），直观展示"如何在一个合规直播平台上做美食直播"；
- 社区目标：开发者 + 垂类社群（美食/潮玩/穿搭…）自托管；star 与贡献者反哺；条件具备后再申请牌照做官方托管运营。

## 7. 合并路线图

| 阶段 | 动作 | 产出 |
|---|---|---|
| **M-1 品牌收敛** | 确定"潮驿为主、炒意厨房为垂类"；对外话术统一 | 品牌架构说明、对外口径 |
| **M-2 代码收敛** | 炒意厨房降为垂类模块；统一部署/合规中台 | 单一代码库 + 统一流水线 |
| **M-3 内容迁入** | 炒意厨房内容/主播/社群迁入潮驿频道 | 美食垂类频道上线 |
| **M-4 开源发布** | 整体开源（含炒意厨房参考垂类）；GitHub+Gitee | 仓库 + README + docker-compose |
| **M-5 多垂类扩展** | 潮玩/穿搭/手作等；条件具备→申请牌照公开运营 | 平台化 |
