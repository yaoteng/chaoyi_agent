# 渠道健康巡检（Channel Inspection）

## When to use
- 月度 / 季度渠道复盘，需要系统给每个下游客户打分。
- 动销异常、库存积压、回款逾期、疑似窜货需要定位根因。
- 业务员拜访资源有限，需要按风险排序分配精力。
- 大客户流失预警。

## Steps
1. **拉取渠道指标**：动销率（销量 / 目标）、库存周转天数、回款账期、活跃度（近 30 天交互）、窜货投诉数。
2. **设定阈值与分层**：红（高危：动销 < 60% 或账期 > 90 天）、黄（预警）、绿（健康）；分层规则可配置。
3. **定位异常与根因**：对红 / 黄客户做归因——是产品不匹配、竞品挤压、资金紧张还是服务断点。
4. **生成处置建议**：按「拜访 / 调货 / 政策倾斜 / 收缩授信 / 清退」给出动作与优先级。
5. **产出看板与待办**：红黄客户清单 + 建议动作 + 责任人，交渠道经理确认。

## Output
- 《渠道健康看板》Markdown（客户 × 指标 × 分层色 × 根因）。
- 异常清单（客户 + 关键指标 + 根因 + 建议动作 + 优先级）。
- 一份「待渠道经理确认」清单（HITL）。

## Guardrails
- 数据仅用于本次巡检，敏感经营数据不出域。
- 建议**不**自动执行清退 / 罚款 / 停货等强动作，须人确认。
- 分层阈值需业务方认可，不得用未对齐的标准下结论。

## Notes
- 可配合 `order-inventory-reconcile`（对账差异佐证根因）与 `visit-plan`（红黄客户优先排拜访）联动。
