# 主播入驻引导（Streamer Onboarding）

## When to use
- 新主播 / 达人 / 机构（MCN）签约，需要启动入驻流程。
- 直播社区运营希望把"签约后靠人盯"的零散动作标准化为流水线。
- 发现新主播首播周期过长、资料反复补交、推流配置卡壳、没人带首播。
- 季度复盘显示新主播首月开播率 / 留存率低于阈值。

## Steps
1. **盘点现有 SOP**：读取既有入驻制度、签约模板、推流接入文档（如 SRS / WebRTC 推拉流地址规范），识别「卡在哪一环」。
2. **生成分层入驻清单**：按角色拆成 4 级——① 实名与资质（身份证 / 年龄核验 ≥18 / 品类资质如食品经营许可证、美妆备案）→ ② 设备与推流配置（OBS / 中控台 / WebRTC 推流，给出 `pushUrl` 与观众侧 `pullUrl`，附 LivePublisher 组件要点）→ ③ 首播策划（选题 / 时段 / 封面 / 预告）→ ④ 开播培训（互动话术 / 合规红线 / 打赏限额）。
3. **起草实名资质收集表**：给出字段清单与校验规则（年龄、实名一致性、品类资质链路完整性），减少来回补件。
4. **生成首播引导话术与开播 Checklist**：开播前（设备自检 / 网络测速 / 合规自查）/ 中（互动钩子 / 控场）/ 后（复盘 / 粉丝沉淀）清单，并明确未成年人保护、版权音乐、打赏限额等红线。
5. **产出接入清单**：列出需运营 / 法务 / 财务手动确认的项（如签约分成、保证金、品类准入）。

## Output
- 一份《入驻阶梯》Markdown（含各级步骤、责任人、预计耗时）。
- 一张实名资质收集表（字段 + 校验规则 + 样例）。
- 一份推流配置指引（pushUrl / pullUrl 获取方式、常见报错排查）。
- 两段首播引导话术（运营私信 + 主播开播 Checklist）。
- 一份「待运营 / 法务确认」清单（HITL）。

## Guardrails
- 只出草稿与建议，**不**替代签约、不替代法务与实名核验动作，需运营确认。
- 实名、身份证、资质等敏感信息仅用于本次入驻，不外泄、不留存于对话之外。
- 分成、保证金、品类准入涉及真金白银与合规，金额 / 政策需运营复核，不得臆造。

## Notes
- 可配合 `live-show-plan` 联动：入驻完成后直接衔接首播选题与排期。
- 可配合 `live-room-ops` 衔接：首播当天的互动运营脚本由该技能接管。
- 适用于个人主播 / 达人 / 机构（MCN）三种形态，按层级与品类差异调整清单颗粒度。
