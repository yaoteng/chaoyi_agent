# 直播内容策划与排期（Live Show Plan）

## When to use
- 新主播首播前需要规划和排期。
- 栏目 / 活动直播需要稳定的内容节奏。
- 发现直播频次忽高忽低、选题靠拍脑袋、预告不统一、切片没人剪。
- 多平台（主直播平台 + 短视频 + 私域社群）分发口径不一致。

## Steps
1. **盘点内容资产与主播特长**：读取主播标签、历史高光、品类热度、粉丝画像，定位内容锚点。
2. **生成选题库**：按品类 / 热度 / 转化潜力分级，给每题标注「适合主播 / 预计时长 / 转化钩子」。
3. **排期**：输出周 / 日直播表，含时段、时长、主播分配、预告发布节奏，避免撞档与空档。
4. **写脚本与话术骨架**：按「开场暖场 → 核心内容 → 高潮转化 → 收尾沉淀」四段给框架，留填空位给主播个性化。
5. **多平台分发计划**：主平台直播 + 短视频切片（高光 15–60s）+ 社群 / 私域预告，明确各端文案与发布时间。

## Output
- 一份《直播排期表》Markdown（日期 / 时段 / 主播 / 选题 / 预告时间）。
- 一个选题库（分级 + 钩子标注）。
- 一份脚本骨架模板（四段式 + 填空位）。
- 一份多平台分发清单（平台 / 内容形态 / 发布时间 / 文案要点）。

## Guardrails
- 选题与脚本只出草稿，最终由主播 / 运营定稿，避免千篇一律失去人设。
- 不替主播承诺无法兑现的福利 / 价格；涉及带货需标注合规话术与资质。
- 版权内容（音乐 / 素材）须走合规曲库，不诱导侵权。

## Notes
- 可配合 `streamer-onboarding`：新主播入驻完成后直接衔接首播选题。
- 可配合 `live-room-ops`：排期确定后，互动脚本由该技能按场次生成。
- 数据复盘可回流到 `audience-growth`，用留存 / 转化反哺下一轮选题。
