# 我把一个直播社区的月运营工时，从 40h 压到了 6h

> 不是靠招人，也不是靠外包，而是给直播社区装了一套"数字社工"——一组开源 Skill。

## 痛点：直播社区死于重复运营
一个中等规模的直播社区，几百个主播、每天上百场直播、几名运营 + 审核。真正消耗精力的不是谈大主播，而是：
- 新主播签约后资料反复补交、推流配置卡壳、首播没人带
- 直播频次靠主播自觉，选题撞车、预告缺失、切片没人剪
- 直播间互动靠临场发挥，弹幕冷场、高价值观众没被接住
- 违规内容靠人工刷，举报经常石沉大海，直播实时风控几乎空白
- 观众留不住、老粉沉默、活动没声量，数据只涨粉不涨转化

这些事单价低、频率高、极度打断心流。很多社区就是被这些"杂活"拖垮增长。

## 解法：潮驿 Agent（Chaoyi Agent）
一个**跨宿主开源 Skill 库**，专门帮直播社区做 agent 化改造。首发 5 个即用 Skill：

| Skill | 解决什么 |
|---|---|
| `streamer-onboarding` | 主播签约→实名资质→推流配置→首播策划→开播培训的标准化流水线 |
| `live-show-plan` | 选题库 / 直播排期 / 脚本骨架 / 多平台分发计划 |
| `live-room-ops` | 弹幕 / 礼物 / 抽奖 / 连麦 / 粉丝团的互动脚本、话术与应急 SOP |
| `community-moderation` | 违规判定 / 五档分级处置 / 举报闭环 / 直播合规红线 |
| `audience-growth` | 用户分层 / 留存召回 / 活动运营 / 直播数据复盘报告 |

**关键设计**：
- 兼容 **Skills 1.0 + MCP 0.4** 双标准，Claude Code / WorkBuddy / Cursor / Codex 都能跑
- `mcp-server/` 纯 Python 标准库实现，**零第三方依赖**，开箱即跑，契合轻量自托管
- 纯 `SKILL.md` + 模板，MIT 协议，fork 即改
- 内置合规红线：未成年人保护、打赏限额、版权曲库、内容安全审核、不得骚扰式群发

## 怎么用（30 秒）
```bash
# 把 skills/ 整个目录交给你的智能体（Cursor / Claude Code 等）
# 对智能体说：
"给新签的 3 个美食主播按 streamer-onboarding 生成入驻阶梯，并衔接首播排期"
```
它就会调用 `streamer-onboarding` Skill，输出可直接确认的《入驻阶梯》和开播 Checklist。

仓库里自带一个完整样例 `examples/reference-livestream/`：一个虚构但可复现的美食直播社区，演示 5 个 Skill 如何把月运营工时从 ~40h 降到 ~6h。

## 为什么不是又一个 Agent 框架？
LangChain / Dify 解决"怎么造 Agent"；Coze 是闭源大厂平台。潮驿解决的是一个被忽略的场景：**已有直播社区怎么低成本 agent 化**。场景聚焦（只做直播社区运营）+ 标准兼容 + 中文优先 + 方法论即产品（附《30 天直播社区 agent 化》路线）。
