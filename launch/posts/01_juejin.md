# 我把一个分销团队的月运营工时，从 40h 压到了 6h

> 不是靠招人，也不是靠外包，而是给分销团队装了一套"数字业务社工"——一组开源 Skill。

## 痛点：分销团队死于重复运营
一个中等规模的快消分销商，下游 1–2 千家门店、几个业务员、一名渠道经理。真正消耗精力的不是谈大客户，而是：
- 新经销商签约后资料反复补交、培训没人跟、首单拖三周
- 政策 / 活动 / 回款催办，群发打开率个位数，电话硬打
- 渠道健康度靠月底拉表，红黄客户经常拖到流失才发现
- 月结对账两人花三天，还常有"发了没收到"的扯皮
- 业务员拜访凭感觉，谁该先跑、进门说什么全靠经验

这些事单价低、频率高、极度打断心流。很多团队就是被这些"杂活"拖垮增长。

## 解法：潮驿 Agent（Chaoyi Agent）
一个**跨宿主开源 Skill 库**，专门帮分销业务做 agent 化改造。首发 5 个即用 Skill：

| Skill | 解决什么 |
|---|---|
| `distributor-onboarding` | 经销商签约→资质→系统开通→培训→首单的标准化流水线 |
| `reach-campaign` | 微信/企微/短信/电话多波次触达的节奏与话术编排 |
| `channel-inspection` | 动销/库存/回款/窜货指标打分、异常定位与处置建议 |
| `order-inventory-reconcile` | 订单/出库/库存/回款四流对账，找差异、缺货、坏账风险 |
| `visit-plan` | 按优先级/地理/产出排业务员拜访路线与话术要点 |

**关键设计**：
- 兼容 **Skills 1.0 + MCP 0.4** 双标准，Claude Code / WorkBuddy / Cursor / Codex 都能跑
- `mcp-server/` 纯 Python 标准库实现，**零第三方依赖**，开箱即跑，契合轻量自托管
- 纯 `SKILL.md` + 模板，MIT 协议，fork 即改
- 内置合规红线：不得绕过短信/外呼合规、不得伪造经营数据、不得骚扰式群发

## 怎么用（30 秒）
```bash
# 把 skills/ 整个目录交给你的智能体（Cursor / Claude Code 等）
# 对智能体说：
"给华东区账期超 60 天的经销商排一轮回款催办触达，3 波、各渠道话术、24h 同渠道去重"
```
它就会调用 `reach-campaign` Skill，输出可直接确认的《触达排期表》和话术草稿。

仓库里自带一个完整样例 `examples/reference-distribution/`：一个虚构但可复现的快消分销商，演示 5 个 Skill 如何把月运营工时从 ~40h 降到 ~6h。

## 为什么不是又一个 Agent 框架？
LangChain / Dify 解决"怎么造 Agent"；Coze 是闭源大厂平台。潮驿解决的是一个被忽略的场景：**已有分销团队怎么低成本 agent 化**。场景聚焦（只做分销运营）+ 标准兼容 + 中文优先 + 方法论即产品（附《30 天分销 agent 化》路线）。
