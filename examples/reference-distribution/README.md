# 示例：一个分销企业如何被「agent 化」

> 这是一个**示意性**改造记录（企业名「云栈分销」为虚构，业务场景真实可复现），用于展示潮驿 5 个分销 Skill 落到真实分销团队的样子。所有涉及对外发送、改账、清退的动作均为**草稿**，由业务方确认后执行（HITL）。

## 背景

「云栈分销」是一家中型快消分销商，下游 1,200 家门店、8 名业务员、1 名渠道经理。改造前：

- 新经销商签约后靠招商个人微信跟进，资料反复补交，平均 **21 天** 才出首单。
- 政策通知群发到经销商群，打开率 < 15%，催办基本靠电话硬打。
- 渠道健康度每月靠人工拉表，红黄客户经常拖到流失才被发现。
- 月结对账 2 人花 3 天，仍常有「发了没收到」的扯皮。

## 应用潮驿 5 个 Skill 之后

| 环节 | 用的 Skill | before | after |
|---|---|---|---|
| 新客入驻 | `distributor-onboarding` | 21 天出首单，资料来回 4 次 | 9 天出首单，资料一次齐 |
| 政策 / 催办触达 | `reach-campaign` | 群发，打开率 15% | 3 波分层触达，响应率 42% |
| 渠道体检 | `channel-inspection` | 月报滞后、靠感觉 | 每周红黄清单，流失预警提前 3 周 |
| 月结对账 | `order-inventory-reconcile` | 2 人 3 天 | 0.5 天出差异表 + 风险清单 |
| 拜访排程 | `visit-plan` | 业务员凭感觉跑 | 路线按风险排，单日产出 +35% |

月度运营工时：约 **40h → 6h**，且红黄客户响应从「事后救火」变成「事前排期」。

## 可直接复制的调用话术

**1. 经销商入驻引导**
> 新签了 3 家二批商（华东），帮我按 distributor-onboarding 生成入驻阶梯，并指出当前卡在资质收集，给每段配企微欢迎话术。

**2. 多渠道触达编排**
> 月底要对账期 > 60 天的经销商做回款催办，用 reach-campaign 排 3 波触达：预热（企微）→ 正式（短信+企微）→ 跟进（电话要点），给各渠道话术并设置 24h 同渠道去重。

**3. 渠道健康巡检**
> 拉本月动销率、库存周转、回款账期，按 channel-inspection 打红/黄/绿，红黄客户给根因和处置建议，红的直接排进下周拜访。

**4. 订单库存对账**
> 月结用 order-inventory-reconcile 对齐订单/出库/库存/回款，标出未发、在途、负库存和长账期应收，给对账差异表和风险清单。

**5. 拜访计划编排**
> 下周拜访用 visit-plan 排：优先红黄客户和新客首月陪跑，按地理就近排路线，每家给 1 个核心目标和 3 句话术要点。

## 怎么套用到你自己的分销业务

1. 把上述 5 个 Skill 接到你现有的经销商 / 订单 / 库存数据源（或先用手动粘贴的 CSV）。
2. 让 4 个 Agent 角色（入驻向导 / 触达管家 / 渠道巡检员 / 拜访统筹）按节奏上岗。
3. 所有对外动作保持 HITL：草稿出来 → 业务方确认 → 由你的 SaaS 通道执行。

> 你也可以用自己公司的真实场景跑一遍，把改造记录 PR 进来——这正是「分销 agent 化」飞轮的一部分。
