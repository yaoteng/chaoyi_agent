# 示例：一个直播社区如何被「agent 化」

> 这是一个**示意性**改造记录（社区名「食光小馆直播社区」为虚构，业务场景真实可复现），用于展示潮驿 5 个直播社区 Skill 落到真实直播社区运营的样子。所有涉及对外发送、封禁、触达的动作均为**草稿**，由运营方确认后执行（HITL）。

## 背景

「食光小馆直播社区」是一个美食直播社区，签约 300+ 美食主播、日均 120 场直播、1 名社区运营 + 2 名审核。改造前：

- 新主播签约后靠运营个人微信跟进，资料反复补交，平均 **21 天** 才完成首播。
- 直播频次靠主播自觉，选题撞车、预告缺失，短视频切片基本没人剪。
- 直播间互动靠主播临场发挥，弹幕冷场、高价值观众没被接住。
- 违规内容靠人工刷，举报经常石沉大海，直播实时风控几乎空白。

## 应用潮驿 5 个 Skill 之后

| 环节 | 用的 Skill | before | after |
|---|---|---|---|
| 主播入驻 | `streamer-onboarding` | 21 天首播，资料来回 4 次 | 9 天首播，资料一次齐，推流配置有指引 |
| 内容排期 | `live-show-plan` | 靠自觉，撞档空档并存 | 周排期表 + 选题库 + 切片分发清单 |
| 直播间互动 | `live-room-ops` | 临场发挥，冷场常见 | 互动脚本 + 话术库 + 应急 SOP |
| 内容风控 | `community-moderation` | 人工刷，举报滞后 | 五档标准 + 举报闭环 + 直播合规红线 |
| 观众运营 | `audience-growth` | 只涨粉不涨转化 | 分层运营 + 召回 + 数据复盘报告 |

月度运营工时：约 **40h → 6h**，且违规处置从「事后救火」变成「事前分级 + 实时预警」。

## 可直接复制的调用话术

**1. 主播入驻引导**
> 新签了 3 个美食主播（华东），帮我按 streamer-onboarding 生成入驻阶梯，并指出当前卡在推流配置，给每段配运营私信话术。

**2. 直播内容策划**
> 下周用 live-show-plan 给这 3 个新主播排首播：出选题库、周排期表、四段式脚本骨架，以及短视频切片 + 社群预告的分发清单。

**3. 直播间互动运营**
> 今晚 8 点一场美食直播，用 live-room-ops 出互动脚本：开场欢迎、关键词应答、礼物感谢节奏、一个抽奖活动规则和应急 SOP。

**4. 社区内容风控**
> 拉本周直播与动态，按 community-moderation 打五档处置标准，给举报处理 SOP 和一份给主播的直播合规红线清单。

**5. 观众运营复盘**
> 月活用 audience-growth 做分层：新客/活跃/沉默/高价值/粉丝团，给沉默用户召回触达草稿，并出一份直播数据复盘报告。

## 怎么套用到你自己的直播社区

1. 把上述 5 个 Skill 接到你现有的主播 / 直播 / 观众数据源（或先用手动粘贴的 CSV）。
2. 让 4 个 Agent 角色（主播入驻向导 / 直播策划师 / 直播间运营官 / 社区守护者）按节奏上岗。
3. 所有对外动作保持 HITL：草稿出来 → 运营方确认 → 由你的社区后台执行。

> 你也可以用自己社区的真是场景跑一遍，把改造记录 PR 进来——这正是「直播社区 agent 化」飞轮的一部分。
